# 1.0.10 — FMP DJUSSC 및 계좌 1 RP 연속조회

## 확인된 RP 원인

사용자가 계좌 1 응답을 제공했다: 연속조회 true, rsp_cd=00218, 계속조회시 다음(연속조회)버튼을 누르시기바랍니다.
기존 앱은 00000/00166만 정상으로 판정해 첫 연속조회 안내에서 실패 처리했다.
NH 공식 SDK도 00165/00218을 연속조회 안내로 설명한다:
https://github.com/PLUG-OpenAPI/nhplug-sdk

- 자산현황에 한해 00218/00165를 다음 페이지 안내로 처리한다. 원래 Input_0 유지, 응답 cts를 다음 요청으로 전달한다.
- 처음 cts_flag=N, 다음 cts_flag=Y. 응답에 flag가 없는 경우 키와 연속조회 코드를 함께 확인한다.
- 반복 키, 키 누락, 중간 페이지 오류, 페이지 상한은 실패 처리한다. 부분 잔고를 정상 합계로 저장하지 않는다.
- 홈에 RP 조회 버튼과 계좌별 요약(성공/실패/건수/원화 평가)을 추가했다. 상세는 펼쳐보기로 분리했다. 해당 버튼도 잔고 캐시를 갱신한다.
- 사용자 실제 응답 코드로 실패 원인은 확인됐지만 수정 APK에서 실계좌 최종 잔액은 아직 미검증이다.

## FMP

- DJUSSC -> FMP stable/historical-price-eod/full, symbol=^DJUSSC. QQQ/QLD/USD 주식은 기존 나무 경로.
- 설정/데이터관리의 FMP 키 카드에서 암호화 저장 및 전체 이력 조회. 키는 채팅/로그에 출력하지 않는다.
- 공식 API 문서: https://site.financialmodelingprep.com/developer/docs
- 10년 이하 요청 구간으로 5000행 제한을 피하고 날짜 정렬/중복 제거. 종목/OHLC 검증. 초기 252거래일 미만 데이터는 전략에 넣지 않는다.
- 출처 변경 시 전체 교체, 이후 증분 갱신. 나무에서 저장했던 지수 일봉과 혼합하지 않는다.
- 1.0.9에서 숨긴 기존 반도체 전략을 복구한다. 기존 계좌/장부 ID와 기록을 유지한다.
- FMP 키가 현재 개발 환경에 없어 인증된 DJUSSC 수신 및 요금제 권한은 미검증. 앱에서 키 저장 후 수신 건수와 기간을 확인해야 한다. FMP 종목 지원/요금제를 검증했다고 보고하지 않는다.

## 검증

- FMP JSON 일봉 파싱, 잘못된 종목/오류 응답 차단, 조회 구간 분할 및 인증/권한/한도 구분 테스트.
- 실제 RP 페이지 파서에 00218 주식 페이지 -> 00166 RP 페이지를 공급하여 다음 키 전달 및 금액 수집 테스트.
- 중간 페이지 오류 시 부분 금액 실패 처리와 반복 키/키 누락 테스트.
- 테스트의 JSON은 재현용 합성 데이터이며 사용자 계좌 잔고가 아니다.
