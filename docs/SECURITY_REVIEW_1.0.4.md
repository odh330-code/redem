# StockSgnal2 1.0.4 보안 점검 및 보완

프로젝트 코드, 인증·주문 흐름, 백업 규칙, 최종 APK 설정을 점검했다. 실제 계좌 조회나 주문 전송은 실행하지 않았다.

## 발견해서 보완한 부분

- 기존 설치 파일의 디버깅 허용을 해제했다. 새 APK는 디버깅 불가로 빌드하며, 개발용 미리보기·테스트 화면도 설치 파일에서 제거했다.
- 계좌번호가 포함된 받은 배당 내역과 사용자가 기록한 전략·체결 내역을 클라우드 백업 및 새 기기 이전 대상에서 제외했다. 기존 인증 키와 계좌 잔고 제외 규칙도 유지했다.
- 계좌·설정 탭에 Android의 화면 보호 기능을 적용했다. 이 탭의 캡처·화면 공유가 제한되며, 매수 확인 창도 보호를 상속한다. 다른 탭에는 이 제한을 적용하지 않는다.
- 토큰 발급·계좌/시세 조회·Massive 배당 조회에서 자동 리디렉션을 차단했다. 매수 통신에는 이미 적용돼 있었다. 앱의 평문 HTTP 사용도 명시적으로 차단했다.
- Massive 키를 URL의 apiKey 매개변수 대신 Authorization 헤더로 보낸다. 배당 조회 오류를 화면에 표시할 때 키 문자열을 가린다.
- 자동 재시도하는 나무 조회 연결은 명시된 조회 경로만 허용한다. 매수·매도·취소·정정 등을 이 연결로 보내는 것을 차단했다.
- 매수 화면에서 나가면 인증 대기 주문을 지워, 늦게 도착하는 인증 결과가 남은 주문을 전송하지 않도록 보완했다.

## 기존 보호 기능 확인

- 나무 AppKey·AppSecret·접근토큰·Massive 키·수동 주문 기록은 기기 Keystore 기반 AES-GCM으로 암호화 저장한다. 검토한 앱 코드에서 이를 출력하는 로그는 발견하지 않았다.
- 매수는 내용 확인과 기기 인증을 거쳐야 하며, 인증한 주문 내용으로 전송한다.
- 주문 전에 암호화한 대기 기록을 동기 저장한다. 저장 실패 시 전송하지 않는다. 기존 주문이 있으면 새 주문을 차단한다.
- 매수 통신에는 자동 재시도·자동 재전송을 사용하지 않는다. 접수와 실제 체결을 구분하며 결과가 불명확하면 신규 매수를 막는다.

## 검증과 범위

22개 단위 테스트, 설치 파일 빌드 및 필수 Android Lint 검사 통과. 최종 APK에서 디버깅 불가, 평문 HTTP 차단, 금융 데이터 백업 제외, 개발용 화면 제거를 확인했다. 기존 1.0.3과 같은 서명으로 덮어 설치할 수 있으며 앱을 삭제할 필요가 없다.

화면 보호·생체 인증·저장소 암호화의 실제 기기 동작은 연결된 휴대폰 없이 확인하지 못했다. 이 결과는 앱 코드와 빌드 산출물 점검이며 외부 침투시험 결과는 아니다. 기존 개인 설치용 서명을 유지했고, 여러 사용자에게 배포할 전용 서명 관리·서명 교체는 이번 범위에 포함하지 않았다.

백업 제외는 이후 자동 백업/기기 이전을 제한하며, 휴대폰에 현재 저장된 설정이나 기록을 삭제하지 않는다. 과거 클라우드 백업이 실제로 삭제됐는지는 확인하지 않았다.
